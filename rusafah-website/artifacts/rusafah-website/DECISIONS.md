# DECISIONS.md — website register

Website-scoped rows. Procedure and semantics are those of the platform register
(`DECISIONS.md` in the platform repository): a `DW-` row is a business or legal
question only RUSAFAH can answer and **nothing downstream of an open row may be
built**; an `EW-` row is a settled engineering choice.

## Resolved — engineering decisions

| ID    | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Rationale                                                                                                                                                                                                                                                                               | Recorded   |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| EW-01 | The website is a **separate repository and separate database** from the platform, on the same stack (Next.js App Router, TypeScript strict, Tailwind, Drizzle/Postgres 16, pnpm, Vitest, Playwright + axe).                                                                                                                                                                                                                                                                                                                                                                 | Public content and leads must not share a database with investor data; marketing release cadence differs. Platform A-01 anticipated a second package — moving this into the platform workspace later is a directory move.                                                               | 2026-09-13 |
| EW-02 | All content that the artboards show is **data in Postgres**, seeded from `db/seed/content.ts`, read through module service functions. Only fixed page copy is in `lib/copy.ts`.                                                                                                                                                                                                                                                                                                                                                                                             | ENGINEERING.md §2.1 — no hardcoded figures in components; the future editor and any projection from the platform's published projects need rows, not JSX.                                                                                                                                    | 2026-09-13 |
| EW-03 | Leads use a **transactional outbox** (`notification_outbox`) written in the same transaction as the lead; a pg-boss worker inside the Next.js server delivers alerts by SMTP with exponential back-off. Rate limiting uses a salted SHA-256 of the client address; raw IPs are never stored.                                                                                                                                                                                                                                                                                | ENGINEERING.md §7 (publication and notification are separate transactions), PDPL minimisation (D-11).                                                                                                                                                                                        | 2026-09-13 |
| EW-04 | The map is **self-hosted**: MapLibre GL, a Protomaps/OpenStreetMap PMTiles extract of Riyadh (zoom ≤ 14, ~10 MB, committed), Noto Sans glyphs and the RTL text plugin under `public/map`. Style colours match the artboards.                                                                                                                                                                                                                                                                                                                                                | The page makes no third-party request; no API key; the PDPL review stays about hosting. Tiles are ODbL-attributed on the map.                                                                                                                                                           | 2026-09-13 |
| EW-05 | Typography: HT Rakik for Arabic (pending DW-01), Alyamama Light for the calligraphic tagline, **Barlow replaces Bahnschrift** for Latin labels and numerals. Adobe Arabic (used on one artboard) is replaced by HT Rakik Light.                                                                                                                                                                                                                                                                                                                                             | Bahnschrift and Adobe Arabic are not licensed for web self-hosting; Barlow is the closest DIN-derived open face.                                                                                                                                                                        | 2026-09-13 |
| EW-06 | Buttons whose target does not exist are **rendered only when the target exists**: «الملف التعريفي» and «برفايل المشروع» appear once a document path is stored; footer legal links follow published documents; social links follow configured URLs.                                                                                                                                                                                                                                                                                                                          | ENGINEERING.md §2.1 — no dead buttons. Supplying the document is a data change, not a code change.                                                                                                                                                                                           | 2026-09-13 |
| EW-07 | Developer routes use `*.dev.tsx` gated by `NEXT_PUBLIC_ENABLE_DEV_ROUTES` (platform E-11); every migration ships a hand-written `.down.sql` verified by `pnpm check:migrations` (platform E-09).                                                                                                                                                                                                                                                                                                                                                                            | Same guarantees as the platform, same mechanism.                                                                                                                                                                                                                                        | 2026-09-13 |
| EW-08 | The admin CMS (`/admin`) authenticates with a signed, encrypted session cookie (`iron-session`, sealed by `SESSION_SECRET`) and salted scrypt password hashes (`node:crypto`, `lib/password.ts`) — no third-party auth framework, no hand-rolled crypto primitive. Every mutation is authorized server-side in the action itself (`requireAdmin()`), never by the page or nav rendering. TOTP MFA is not yet built; see **DW-10**.                                                                                                                                          | A small number of internal editors, one Next.js app, no need for OAuth/social login or a separate auth service; still boring, well-supported building blocks (ENGINEERING.md "prefer boring, well-supported solutions", "never write custom crypto, auth").                                  | 2026-09-15 |
| EW-09 | Every admin mutation writes one `audit_log` row (actor, entity, before, after) in the same transaction as the change. Uploaded images are re-encoded through `sharp` before being written to disk (verifies the file is really an image, strips metadata, caps dimensions) and stored behind a `StoragePort` seam (`modules/media/storage-port.ts`) — local disk under `MEDIA_UPLOAD_DIR` today, swappable for an S3-compatible adapter once hosting is decided (platform D-11) without touching a call site.                                                               | Same audit guarantee the platform requires of the investor system (ENGINEERING.md §7); uploads are a common injection/storage-cost vector worth validating once, centrally.                                                                                                                  | 2026-09-15 |
| EW-10 | CRM connectivity follows the platform's deferred-system pattern (ENGINEERING.md §6): a `CrmPort` interface (`modules/integrations/crm`), a `NotConfiguredError` stub, and a feature flag (`CRM_PROVIDER`). The one real adapter is a generic REST/PostgREST webhook sink, not a specific vendor's SDK, because which CRM to use was not decided (**DW-09**) and its field-naming schema is not this project's to guess. A sync row is enqueued in the same transaction as the lead, through the existing `notification_outbox`, but only when a provider is actually configured. | Lets a CRM (the Supabase-backed one already on the development machine, or another) be connected by configuration alone once **DW-09** is answered, without rework; matches the LedgerPort/DistributionPort precedent already established for the platform's own deferred integrations. | 2026-09-15 |
